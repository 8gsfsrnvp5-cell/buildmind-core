# Сравнение BuildMind V2.0 с прототипом Cursor

Дата сравнения: 27 августа 2026 года.

Источник сравнения: `buildmind_mvp_github_starter 1.zip`.

## Что находится в архиве Cursor

Архив содержит четыре рабочих файла:

- `index.html` — одна страница контроля снабжения;
- `style.css` — оформление карточек, таблицы и статусов;
- `app.js` — массив материалов и расчёт снабженческого риска;
- `README.md` — описание запуска и ближайшего этапа.

Прототип Cursor не выполняет OCR, не читает PDF или Excel, не распознаёт ВОР и ГПР, не сопоставляет работы, не ведёт реестр документов и не сохраняет данные после обновления страницы. Три материала в нём заранее записаны в `app.js`.

Технические ограничения исходного `app.js` Cursor:

- пользовательские значения вставляются в `innerHTML` без экранирования;
- при пустой дате начала расчёт может перейти к дате 1970 года вместо понятной ошибки;
- отрицательные остатки, резервы и сроки не проверяются единым валидатором;
- подтверждённая поставка без даты может получить статус «ОК»;
- прошедшая дата поставки не всегда распознаётся как задержка;
- прошедшая крайняя дата заказа создаёт предупреждение даже тогда, когда свободного склада уже достаточно.

## Сильное решение Cursor

Главная полезная цепочка реализована понятно и без лишних зависимостей:

```text
дата начала работы
→ страховой запас
→ дата потребности
→ срок поставки
→ крайняя дата заказа
→ свободный остаток
→ подтверждённая поставка
→ дефицит
→ риск
→ рекомендуемое действие
```

Формулы Cursor:

- свободно = `max(остаток − резерв, 0)`;
- доступно = `свободно + подтверждено поставщиком`;
- дефицит = `max(потребность − доступно, 0)`;
- дата потребности = `начало работы − страховой запас`;
- крайняя дата заказа = `дата потребности − срок поставки`.

## Что уже было сильнее в BuildMind V2.0

До данного изменения BuildMind уже имел:

- локальное сохранение материалов;
- редактирование и постоянные ID;
- мягкое исключение и восстановление;
- неизменяемую историю «до → после»;
- проект, объект, работу и ответственного;
- загрузку и распознавание документов;
- ВОР, ГПР и их сопоставление;
- источники и страницы;
- реестр документов и редакции;
- сохранённый снимок анализа;
- оперативный центр по нескольким проектам;
- фильтры рисков, поставок и обеспеченности.

## Обнаруженный разрыв BuildMind

Снабженческий расчёт существовал, но результат PR14 не был полностью связан с ним:

- сроки из ГПР отображались в таблице, но не создавали рабочие контексты;
- найденные материалы отображались отдельно и не имели безопасного пути в контроль снабжения;
- одинаковые формулы риска были продублированы в нескольких местах и могли расходиться;
- подтверждённая поставка без даты могла ошибочно выглядеть обеспеченной;
- прошедшая дата поставки могла не получить критический статус;
- прошедшая крайняя дата заказа могла создавать ложное предупреждение даже при достаточном свободном остатке.

## Что перенесено и улучшено

Добавлен единый `procurementRiskEngine.js`, который используется таблицей материалов и оперативным центром.

Добавлен `procurementIntegration.js`, связывающий сохранённый анализ PR14 со снабжением.

Добавлено создание рабочих контекстов из строк ГПР:

- проект и объект берутся из паспорта проекта;
- работа, начало и окончание берутся из ГПР;
- страховой запас по умолчанию — 2 дня;
- страховой запас выбранного контекста можно изменить, повторный импорт ГПР его не сбрасывает;
- повторный импорт не создаёт дубликаты;
- изменившиеся сроки обновляют только контексты, ранее созданные из анализа;
- ручные контексты автоматически не перезаписываются;
- неполные или перевёрнутые даты пропускаются;
- источник и признак проверки сохраняются.

Для материалов анализа добавлено действие «В контроль снабжения»:

- позиция сначала переносится в форму;
- инженер проверяет работу, количество, ответственного, склад и поставку;
- только после подтверждения материал участвует в расчёте;
- повторный перенос одной позиции блокируется;
- документ и страница сохраняются как источник.

## Что намеренно не копировалось

- заранее записанные демонстрационные материалы;
- фиксированные названия проекта, объекта и работы;
- отсутствие сохранения данных;
- открытие только двойным кликом как единственный способ проверки;
- упрощённый статус «ОК» для подтверждённой поставки без даты;
- отдельный новый проект вместо продолжения существующего BuildMind.

## Итог

Удобная логика Cursor встроена в существующую архитектуру BuildMind. Версия Cursor остаётся полезным эталоном простоты интерфейса снабжения, а BuildMind сохраняет более сильные функции распознавания, истории, источников, инженерного подтверждения и сквозной работы ВОР → ГПР → материалы → риск.
